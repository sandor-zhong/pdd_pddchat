# 申诉运营看板

## 查看日志

打开 https://flowtry.top/pdd-logs/ 即可免密码查看订单进度、申诉统计、明细和原始日志。任何知道链接的人都能查看店铺和订单信息。
该文件含管理员查看密码和本机上传凭证，已被 Git 忽略，不打进安装包、不上传到公开更新目录。
管理员设备配置接口仍需原有密码会话（有效期12小时），普通页面不提供生成设备配置入口。上传接口仍校验各电脑的独立凭证。

页面可按电脑、店铺（完整名称）、任务、日志级别和关键词筛选。支持暂停/继续、自动滚动、加载更早日志。
电脑每 15 秒更新在线状态，45 秒没有上报显示离线。页面最多保留 1000 条，加载历史时会从另一端移除超限行。
网页只查看日志和生成设备配置，不能操作申诉任务。

## 运行电脑接入

当前源码客户端已经保存 `gui/state/remote_logging.json`，重启源码 GUI 后生效。
已安装的旧客户端需要先发布包含本次代码的新版本；目前没有重新打包。

其他运行电脑：

1. 由开发通过管理员登录接口和设备配置接口生成独立配置。
2. 将下载的 JSON 放到对应运行电脑。
3. 在程序的“帮助 → 远程运行日志”中导入，勾选启用，保存。
4. 设置窗口显示最近上报时间后，网页即可看到该电脑在线和新日志。

每台电脑使用各自生成的配置。不要复制同一配置给多台电脑，否则它们会显示在同一设备下。
开启后仅上传运行控制窗口新增的日志，不追溯旧日志文件，不自动上传聊天库、截图或环境配置文件。
订单步骤只展示日志明确关联的订单，不将操作提交成功当作平台审核通过。展开订单可下载诊断信息给开发。原始日志仍可筛选。

## 传输和断线行为

- GUI 只向容量 2000 的内存队列写入；独立线程落盘、上传，不等待网络。
- 通常每 2 秒批量 HTTPS 上报，服务端 SSE 每秒检查新记录；正常显示延迟约 2～3 秒，受网络影响。
- SQLite 本地待传缓存按内容字节数限制 20 MB；内存队列或磁盘缓存超限会丢弃记录并显示数量。突然退出前尚未落盘的内存日志可能丢失。
- 网络错误按 4～30 秒间隔重试；服务端确认整个批次后才清除本地待传记录。
- 事件使用唯一编号去重；网页断线自动重连，以 `Last-Event-ID` 续传。暂停后继续也从最后显示位置补取。
- 服务器保留最近 7 天、最多 20000 条记录（先达到的限制生效）；已过保留期的记录无法续传。
- 常见 `password`、API key、Bearer 凭证会脱敏；这不能替代业务代码避免写入敏感信息。

## 服务端运维

- 服务：`pddchat-log-relay.service`，监听 `127.0.0.1:8765`。
- 程序：`/opt/pddchat-log-relay`。
- 数据：`/var/lib/pddchat-log-relay/logs.db`。
- 私有环境配置：`/etc/pddchat-log-relay.env`，只存密码哈希。
- nginx：`/etc/nginx/snippets/pddchat-log-relay.conf`，SSE 关闭代理缓冲。
- 原站点配置已备份到服务器 `flowtry.top.before-logs-*` 和本地 `outputs/log-relay-preflight/`。
- 运行用户：`pdd-log-relay`，只对日志数据目录有写权限。
- 原有 `/updates/pdd_appeal/` 更新服务保留。

检查服务：

```bash
systemctl status pddchat-log-relay
journalctl -u pddchat-log-relay -n 100 --no-pager
nginx -t
```

开发验证（项目根目录，GUI 虚拟环境需要 httpx）：

```powershell
.\gui\.venv\Scripts\python.exe -m unittest tests.test_remote_logs -q
.\gui\.venv\Scripts\python.exe server/log_relay/verify_live.py
```

重新部署独立日志服务：

```powershell
.\gui\.venv\Scripts\python.exe server/log_relay/deploy.py
```

使用发布工具已有的受信任 SSH 主机配置和密钥。再次部署保留数据库和既有凭证；若本地凭证与服务器不一致则停止覆盖。
不要删除本地 `state/remote-log-access.json` 后直接重部署；应先恢复备份。

## 辅助查询同步

2026-11-06修复：统计快照同步独立于日志/进度上传调度，每60秒同步；失败10秒后重试，恢复后更新成功时间。失败类型通过认证的 `api/report-status` 上报并在看板显示，避免电脑在线但统计缺失却无提示。客户端改动须更新并重启后生效。

统计接口为每台电脑返回来源和完整性。无快照时，从当前保留日志中仅提取逐单明确的“已提交/已提交复议”最终回执，按电脑、店铺、类型、订单去重；失败、模拟、汇总计数、待确认提交均不计入。此来源仅为已确认数量下限，受日志保留范围限制，复议/售后同一订单多条记录也可能漏记；网页显示“至少N单”，没有可确认记录时显示“待同步”，不显示为确定的0。完整快照到达后取代日志兜底，不叠加计数；结果以快照为准。快照过期或缺失时均明确提示数据不完整。

新客户端每60秒使用 GUI 的 `query_report` 从本机数据库生成全部真实提交记录快照，服务端按电脑原子替换保存；失败保留上次成功快照。页面每10秒刷新并显示同步时间，超过120秒提示过期。现有运行进程须重启，新电脑须安装包含这些变更的客户端。

页面支持提交日期（北京时间）、店铺、类型、电脑筛选，部分通过计入通过率开关及 CSV 导出。通过率只使用已审核记录。跨电脑相同订单可能重复，按电脑列明，不擅自合并。查询快照独立于7天日志保留，不随日志清理，停用设备后仍显示最后同步时间。单快照上限16MB，超出时上传失败并保留旧快照。

默认 `public_view=True`，可在应用设置字典显式改为 False 恢复查看鉴权。密码与上传凭证不会返回给公开查看接口。

## 运营看板布局（2026-11-06）

调度器在本轮开始按“今日已完成”跳过的店铺显示为“今日已完成／本轮无需重复处理”，不再显示等待名额。客户端处理无店铺归属的 `round_skip_done` 批量事件并同步终态；服务端为旧客户端仅依据同设备、同GUI会话、本轮开始后的明确跳过日志修正未初始化的等待行，不改变实际调度或重复执行已完成店铺。

提交统计展示已简化：各店铺按电脑和店铺合并为一行，仅显示负向申诉、复议、售后申诉、合计，不展示审核结果。卡片始终显示当前已收到记录的数字，不加“至少”或“待同步”；来源、快照缺失及可能不完整的说明独立显示在表格上方，不改变数字口径。

- 运行总览：每5秒刷新。任务卡显示本轮任务、分配店铺、总体进度与预计剩余时间；每家店显示已处理/总队列/待处理、当前步骤及异常。总体进度沿用 GUI 按店铺等权的口径，结束不等于提交或审核成功。未扫描到队列时不推算数量。45秒未更新标记过期。
- 订单动态：直接显示北京时间的最后更新时间和开始时间；有错误记录的订单保持红色警示，重试后仍可查看先前错误。展开显示步骤时间线、错误原因并下载诊断。
- 今日申诉统计：默认北京时间今天，显示真实提交总量、三类申诉数量及店铺汇总，不展示订单明细，不请求包含订单详情的旧 reports 接口。可选择其他提交日期。
- 诊断日志：单独标签页保留原始日志筛选与断线续传。

运行端通过 `api/progress` 同步 GUI 当前任务快照，网络上传在后台线程进行。每轮任务使用独立 task_id；服务端每台电脑只保留最新一轮，不用历史日志猜测当前分配任务。客户端必须更新并重启才能首次提供这些进度数据。

## 订单错误截图（2026-11-06）

运行端保存订单错误现场后，将截图与同一订单的错误事件一起同步。订单动态显示“有错误截图”，展开可看缩略图，点击查看原图。截图捕获失败不影响原有错误日志；历史日志不会自动补生成截图。

仅允许上传项目 debug 目录中的 PNG，单张不超过2MB。图片使用独立的持久化重试队列，本地队列上限20MB；服务端保留7天，最多100张且总计不超过100MB，达到上限清理最早图片。图片的查看权限与日志看板一致。

服务端和网页部署后，运行电脑仍需安装包含这些改动的新版客户端并重启，才能自动上传此后捕获的错误截图。此次代码修改不自动生成安装包。
